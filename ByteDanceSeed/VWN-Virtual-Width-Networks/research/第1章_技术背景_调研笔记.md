## 1.1 宽度（hidden dimension）扩展的代价：O(D²) 的硬约束与"深优于宽"的实证

1. **参数量与算力对 hidden dim D 是二次的。** 标准 Transformer 每层 FFN 的两个矩阵为 D×4D 与 4D×D（合计 8D²），Attention 的 Q/K/V/O 为 4 个 D×D（合计 4D²），即每层约 12D²；Kaplan 等给出非嵌入参数量 N ≈ 2·d_model·n_layer·(2·d_attn + d_ff) = **12·n_layer·d_model²**（标准设定 d_attn = d_ff/4 = d_model），并给出每 token 训练算力 C ≈ 6N。推论：D 翻倍 → 参数量与训练 FLOPs ×4。[arXiv:2001.08361](https://arxiv.org/html/2001.08361v1)

2. **GPT-3 的配置佐证 N ∝ n_layer·d_model²，并明确 d_ff = 4·d_model。** 从 125M（12 层 / d_model 768）到 175B（96 层 / d_model 12288），参数量放大 ~1400× 时，宽度维度贡献 16×、深度维度仅 8×；论文原文写明"we always have the feedforward layer four times the size of the bottleneck layer, d_ff = 4*d_model"。[arXiv:2005.14165](https://arxiv.org/abs/2005.14165)

3. **经典缩放定律其实主张"形状不敏感"——这是后续争论的起点。** Kaplan 等发现：固定非嵌入参数量 N 时，n_layer、d_model、n_heads、d_ff 影响很弱；宽深比（aspect ratio）可变化 40 倍而 loss 仅微变，(n_layer, d_model)=(6, 4288) 与 (48, 1600) 的 loss 差在 3% 以内。摘要原句："Other architectural details such as network width or depth have minimal effects within a wide range."（注意：40 倍这一论述位于正文 §3.1 的 Figure 5 图注，**不在摘要**。）[arXiv:2001.08361](https://arxiv.org/html/2001.08361v1)

4. **MobileLLM 用同参数预算的对照实验直接反驳了"宽深无关"。** ~125M 档：最宽最浅的 4 层 / dim 1280（163.2M 参数）8 任务平均 **43.3**，而更窄更深的 30 层 / dim 512（135.0M）达 **44.8**、62 层 / dim 384（134.3M）达 **44.7**；~350M 档：5 层 / dim 2048（388.0M）平均 **47.1**，32 层 / dim 896（380.3M）达 **49.8**。论文原句："Contradictory to the scaling law (Kaplan et al., 2020), we demonstrate that depth is more important than width for small LLMs."，并给出亚十亿规模模型的**最优深度约为 30 层**（该句在附录 C）。[arXiv:2402.14905](https://arxiv.org/html/2402.14905v2)

5. **宽度扩展还有"隐性代价"——超参整定。** 标准参数化（SP）下 Transformer 的最优学习率随宽度漂移，μP 下则对宽度稳定；μTransfer 从 13M 代理模型迁移超参即超过 BERT-large（350M），从 40M 迁移超过 GPT-3 6.7B，调参成本仅为预训练的 7%。这说明加宽的收益高度依赖参数化与超参整定。[arXiv:2203.03466](https://arxiv.org/abs/2203.03466)

6. **但"深宽权衡"并非单向结论，存在反证。** CompleteP（Cerebras）认为历史上"深度不划算"部分源于参数化造成的假象——SP/μP 下深层模型的超参被 detune 且落入 lazy regime，因此深模型被系统性低估。其论文报告：在 1.5B 非嵌入参数下，最优宽深比从 μP 的 N:L = 38.7 放宽到 **11.8**（仍落在最优 loss 1% 内），并自报带来 **12–34%** 算力效率提升（作者自报数字，非独立复现）。[arXiv:2505.01618](https://arxiv.org/abs/2505.01618)

7. **深度也并非无条件越好。** TinyBERT 在宽度固定为 768 时，4 层即可达到教师 BERT-base 在 GLUE 上性能的 **>96.8%**（同时小 7.5×、推理快 9.4×），6 层即与教师持平——说明最优深宽比与规模、任务、训练方式强相关，BERT-base 的 12 层存在明显冗余。[arXiv:1909.10351](https://arxiv.org/abs/1909.10351)

8. **另一条路线是"改变宽度的组织方式"而非单纯加大 D。** 细粒度 MoE 缩放定律（引入 granularity 超参精确控制专家尺寸）证明："把专家尺寸设为与完整 FFN 相同"这一常规做法在**几乎所有**算力预算下都非最优；且 dense 与 MoE 的效率差距随预算扩大，超过 10^25 FLOPs 时可超过 **40×**。[arXiv:2402.07871](https://arxiv.org/abs/2402.07871)

## 1.2 MoE 的现实瓶颈：只扩 FFN 内部维度，宽度仍是 hidden dim

1. **MoE 只扩专家维度，d_model 完全不动（原文实证）。** DeepSeek-V3 为 61 层、hidden dimension **7168**，仅把前 3 层以外的 FFN 换成 MoE：每层 1 个共享专家 + 256 个路由专家，**每个专家的中间维度仅 2048**（远小于 dense 常规的 4×7168 = 28672），每 token 激活 8 个路由专家 + 1 个共享专家。671B 参数几乎全部由"专家数 × 专家隐层"堆出，而 token 的表征宽度始终是 7168。[arXiv:2412.19437](https://arxiv.org/html/2412.19437v2)

2. **Qwen2 提供了最干净的同族对照。** Qwen2-7B 与 Qwen2-57B-A14B 的 Hidden Size **完全相同（均为 3584）**、层数也**同为 28**；MoE 版只是把 FFN 换成 64 个路由专家（每个专家 Intermediate Size 仅 2560）+ 8 个共享专家，参数量从 7B 涨到 57B，**而表征宽度零变化**（论文亦写明 "Qwen2-57B-A14B is upscaled from Qwen2-7B"）。注意表注："# Activated Experts excludes the shared experts"，故每 token 实际激活 16 个专家。[arXiv:2407.10671](https://arxiv.org/html/2407.10671v4)

3. **Mixtral / Switch Transformer 的机制表述同源：能力增长走参数轴而非宽度轴。** Mixtral 明确"the feedforward blocks are replaced by Mixture-of-Expert layers"、"an expert is a standard feedforward block"；Switch Transformer 把该机制概括为"sparsely-activated model — with outrageous numbers of parameters — but a constant computational cost"——即用稀疏激活换容量、计算量恒定。[arXiv:2401.04088](https://arxiv.org/abs/2401.04088)

4. **all-to-all 通信是头号工程瓶颈，官方给出了量级。** V3 报告原文：跨节点专家并行带来的通信开销使**计算/通信比恶化到约 1:1**；训练采用 16-way PP + **64-way EP（跨 8 个节点）** + ZeRO-1 DP；all-to-all 的 dispatch/combine 需占用 H800 的 132 个 SM 中的 **20 个**；解码阶段最小部署单元为 40 节点 / 320 GPU，MoE 部分 EP320。[arXiv:2412.19437](https://arxiv.org/html/2412.19437v2)

5. **带宽不对称直接决定了系统设计。** V3 报告给出 NVLink 160 GB/s ≈ IB 50 GB/s 的 3.2× 差距，因此限制每个 token 最多发往 4 个节点以压缩 IB 流量、再在节点内用 NVLink 转发，最终每 token 平均每节点选 3.2 个专家，且通信可被完全重叠、只需 20 个 SM 即可打满 IB/NVLink 带宽。同源论文把这件事算到推理时延上：以 400Gbps CX7 IB、每设备 32 token、hidden≈7K、每 token 8 路由 + 1 共享专家计，两次 all-to-all 需 (1B+2B)×32×9×7K / 50GB/s = 120.96 μs，61 层合计 14.76 ms TPOT ≈ 67 tok/s，结论是"**the upper limit of MoE inference speed is dictated by interconnection bandwidth**"。[arXiv:2412.19437](https://arxiv.org/html/2412.19437v2) · [arXiv:2505.09343](https://arxiv.org/html/2505.09343v2)

6. **硬件侧的硬约束：H800 被迫放弃张量并行。** H800 的 NVLink 因合规从 900 GB/s 被削减到 400 GB/s，scale-up : scale-out 带宽比约 4:1（NVLink 标称 200GB/s、实测约 160GB/s；单张 400Gbps IB 标称 50GB/s、论文保守按 40GB/s 有效带宽计）。V3 用 8 张 400Gbps IB 网卡把 all-to-all 做到 >40 GB/s，并**在训练中明确规避张量并行**（原文小标题 "Avoidance of Tensor Parallelism (TP)"），TP 仅在推理时选择性使用以改善 TTFT/TPOT。同文给出 GB200 NVL72（900GB/s 单向）下 0.82 ms TPOT ≈ 1200 tok/s 的理论上限，作者注明"purely theoretical and has not been empirically validated"。[arXiv:2505.09343](https://arxiv.org/html/2505.09343v2)

7. **显存：问题被专家并行"摊薄"而非消除。** V3 为 671B 总参 / 37B 激活，FP8 存储带来"reduced GPU memory usage"；官方说明因 EP 规模很大，DualPipe 保留两份模型参数副本也不显著增加显存。vLLM 官方文档则给出负载均衡冗余专家的具体显存代价：DeepSeek-V3 每个 EP rank 多一个冗余专家约需 **2.4 GB**，并明确警告 EPLB 会挤占 KV cache、不适合显存受限场景。按 FP8 每参数 1 字节折算 671B 权重约 671GB 量级（该数字为本笔记按位宽换算，官方未直接给出）。[arXiv:2412.19437](https://arxiv.org/html/2412.19437v2) · [vLLM docs](https://docs.vllm.ai/en/v0.11.0/serving/expert_parallel_deployment.html)

8. **负载不均衡 / router collapse 与其工业界兜底手段。** V3 引用 Shazeer 2017 指出"an unbalanced expert load will lead to routing collapse and diminish computational efficiency in scenarios with expert parallelism"，同时指出辅助损失过大会损害性能——这正是其采用 **auxiliary-loss-free** 策略的动机：给每个专家一个 bias b_i（仅加在 top-K 路由打分上，门控值仍由原始 affinity 得出），每步对过载专家减 γ、欠载专家加 γ。学术侧：ST-MoE 给出 all2all 作为 MoE 路由的公共通信原语，并指出容量因子放大可减少丢 token 但同步抬高显存与计算（其采用 α=10⁻² 辅助损失做折中）；Expert Choice Routing 明确指出"糟糕的路由（例如导致负载不均衡）会让某些专家训练不足、造成欠/过特化"，并报告训练收敛时间改善 **>2×**；另有专文论证路由机制会促使 token 向专家质心聚集、存在**表征坍塌**趋势。[arXiv:2412.19437](https://arxiv.org/html/2412.19437v2) · [ST-MoE](https://arxiv.org/abs/2202.08906) · [Expert Choice](https://arxiv.org/abs/2202.09368) · [Representation Collapse](https://arxiv.org/abs/2204.09179)

9. **推理期低 batch 是真问题。** V3 报告自述解码阶段"the batch size per expert is relatively small (usually within 256 tokens), and the bottleneck is memory access rather than computation"，prefill 阶段则用 32-way EP 以保证每个专家有足够大的 batch；第三方实测（AMoE）显示单个专家层吞吐随 batch 近乎线性增长直到 batch=128（即更小 batch 就是浪费，因为受限于从 HBM 加载专家权重），并在 SGLang+EP 服务 Mixtral 8x7B 时观测到最热专家造成的等斜滞，GPU 空转时间最高可占 GPU 时间的 **70%**。[arXiv:2412.19437](https://arxiv.org/html/2412.19437v2) · [arXiv:2505.08944](https://arxiv.org/html/2505.08944v2)

## 1.3 残差连接的瓶颈：固定宽度的残差流

1. **Hyper-Connections 的 motivation：残差连接把"层间连接强度"预先写死。** Pre-Norm 解决了梯度消失却造成深层表示坍塌（hidden features 高度相似、深层的边际贡献随层数增加而下降），Post-Norm 缓解表示坍塌却重新引入梯度消失——"梯度消失与表示坍塌是跷跷板的两端"。关键原句："The key issue is that residual connections, including both Pre-Norm and Post-Norm variants, **predefine the strength of connections** between the output and input within a layer."[arXiv:2409.19606](https://arxiv.org/html/2409.19606v3)

2. **HC 的核心解法就是"加宽残差流"，且开销几乎可忽略。** 把 hidden state 复制成 n 份（hyper hidden matrix H ∈ R^{n×d}，n 即 **expansion rate**），每份各有 depth-connection，副本之间再通过 width-connection 交换信息。原文："although HC seem to increase the network's width by n times, the additional parameters and computational cost are almost negligible." 可核验的开销：OLMo-1B-DHC×4 的额外 FLOPs 仅 **+0.200%**（0.0049G / 2.3583G）、参数量 **+0.03349%**（+394,048 / 1.1768B）；原因是 HC 开销 O(d_model·n·(n+1)) ≪ attention 投影 O(4·d_model²) < FFN O(2·d_model·d_ffn)。[arXiv:2409.19606](https://arxiv.org/html/2409.19606v3)

3. **HC 的收益与饱和点：n=1 不够，必须真的加宽。** OLMoE-1B-7B-DHC×4 相比 baseline **收敛快 1.8×**，500B token 时 ARC-Challenge 提升 **6 分**；n 的消融显示 **n=1 时 DHC 反而劣于 baseline**（V2 Eval Loss 2.819 vs 2.811；下游 62.3 vs 62.5）——说明"可学习的连接强度"本身不足以解决问题，必须真正扩张残差流；n=4 最优，增至 n=8 收益很小。[arXiv:2409.19606](https://arxiv.org/html/2409.19606v3)

4. **"残差流是有限带宽通道"的经典论述（Anthropic Transformer Circuits）。** 原文："dimensions of the residual stream become something like 'memory' or 'bandwidth'."；单个 MLP 层通常有 **4×** 残差流维度的神经元，因此在 50 层模型的第 25 层，残差流前后各要面对约 **100×** 自身维度的神经元，只能以 superposition 通信；作者把这类张量称为 **"bottleneck activations"**（定义为"a lower-dimensional intermediate between two higher dimensional activations"），并推测正因带宽需求极高，才演化出专门的 "memory management" 机制（部分 MLP 神经元与 attention head 的 W_O W_V 具有大负特征值，用于清除残差流中的信息）。**注意：该文无 arXiv 编号**，正确引用是 Transformer Circuits Thread。[Transformer Circuits](https://transformer-circuits.pub/2021/framework/index.html)

5. **DenseFormer 从"带宽配额"角度给出同构动机与机制。** 其假设是：skip connection 迫使深层表示既要维持当前 token 表示、又必须预测下一 token（存在内在歧义），跨块直连让模型能更直接复用早期特征——"**without requiring to allocate as much bandwidth to propagate them through multiple layers**"。实现上 DWA 在每层对当前块输出、所有历史块输出与 embedding 做加权平均，额外参数仅 d(d+3)/2。[arXiv:2402.02622](https://arxiv.org/abs/2402.02622)

6. **DenseFormer 的量化收益与一个关键消融。** 48 块 DenseFormer 的 perplexity 只有 72 块标准 Transformer 才能匹敌，而后者参数量与显存占用**大 45%**；48 块 4x5-DenseFormer 匹配 72 块基线的 perplexity 同时推理**快 1.4×**。最关键的是：仅给所有 skip connection 加可学习缩放（Skips with Gains）**不能**带来同等提升——说明瓶颈不是"缩放残差强度"，而是**缺乏对早期层的直接访问**。[arXiv:2402.02622](https://arxiv.org/abs/2402.02622)

7. **正面验证"残差流宽度是可独立缩放的轴"。** Residual Matrix Transformers（ICML 2025）直接把残差流定义为"a memory bus where transformer layers both store and access features"，用 outer product memory matrix 替换残差流，结论是残差流尺寸**可以独立于计算量和模型规模**缩放；报告达到相同 loss 时比 Transformer 少用 **58% FLOPs、25% 参数、41% 训练 token**。其后续工作 xHC（2026-07 技术报告，**非同行评审**）指出 HC 族方法通常止步 N=4，瓶颈是"流数增加后 write-back 信息不足"与"residual-mixing 生成成本随 N 三次方增长"，并以稀疏残差流突破到 N=16（报告 18B MoE 上比 mHC 高 4.0 分）。[arXiv:2506.22696](https://arxiv.org/abs/2506.22696) · [arXiv:2607.14530](https://arxiv.org/abs/2607.14530)

8. **Pre-Norm / Post-Norm 的理论出处，以及一个必须写清的限定。** 梯度理论出自 Xiong et al.（ICML 2020）：Post-LN 在初始化时输出层附近参数的期望梯度很大、大学习率导致不稳定（这正是 warm-up 必要的原因），而 Pre-LN 的梯度 well-behaved，可去掉 warm-up。另一权威来源 DeepNet 以"兼顾 Post-LN 性能与 Pre-LN 稳定性"为目标把 Transformer 稳定扩展到 1000 层。**限定**：rank collapse 的严格结论来自 Dong/Cordonnier/Loukas，其证明针对的是"**禁用 skip connection 与 MLP 的纯自注意力**"输出以 doubly exponential 收敛到 rank-1；论文同时指出 skip connection 与 MLP 阻止了该退化，并明确证明 **LayerNorm 不能缓解 rank collapse**（"Since right multiplication cannot increase the rank of a matrix, we conclude that layer normalization does not mitigate the rank collapse"）。因此"Pre-Norm 导致表示坍塌"在文献中是**工程经验性关联**，不宜表述为已被证明的因果关系。[arXiv:2002.04745](https://arxiv.org/abs/2002.04745) · [arXiv:2203.00555](https://arxiv.org/abs/2203.00555) · [arXiv:2103.03404](https://arxiv.org/abs/2103.03404)

## 1.4 硬件现实：为什么"超宽激活"对 GPU 不友好

1. **内存墙是 20 年尺度的结构性趋势，有硬数字。** 峰值服务器 FLOPS 每 2 年增长 **3.0×**，而 DRAM 带宽仅 **1.6×**/2 年、互联带宽仅 **1.4×**/2 年；20 年累计峰值算力 **+60,000×**，而 DRAM 带宽仅 **+100×**、互联带宽仅 **+30×**。该文并指出 decoder-only 自回归推理（batch=1）的算术强度比 encoder 的矩阵-矩阵运算小 "orders of magnitude"，因此显存带宽成为主导瓶颈（GPT-2 与 BERT-Base FLOPs 相当但延迟显著更高）。[arXiv:2403.14123](https://arxiv.org/abs/2403.14123)

2. **硬件拐点（arithmetic intensity 门槛 = 密集算力 ÷ 带宽）在 150–330 FLOP/byte 区间**，且两代之间几乎原地踏步：
   - **H100 SXM5**：BF16/FP16 Tensor Core **989.4 TFLOPS**（稀疏 1978.9），HBM3 约 3 TB/s（SXM5 规格 3.35 TB/s）→ 拐点约 **295–330 FLOP/byte** [NVIDIA H100 whitepaper](https://resources.nvidia.com/en-us-hopper-architecture/nvidia-h100-tensor-c)
   - **A100**：BF16 312 TFLOPS（稀疏 624），80GB SXM4 带宽 **2,039 GB/s**（40GB PCIe 为 1,555 GB/s）→ 拐点约 **153 FLOP/byte** [NVIDIA A100 datasheet](https://www.nvidia.com/content/dam/en-zz/Solutions/Data-Center/a100/pdf/nvidia-a100-datasheet-us-nvidia-1758950-r4-web.pdf)
   - **B200**：FP16/BF16 **2.2 PFLOPS** 密集（4.5 稀疏）、**7.7 TB/s** HBM3e → 拐点约 **286 FLOP/byte**，与 H100 基本持平 [NVIDIA Blackwell brief](https://resources.nvidia.com/en-us-blackwell-architecture)

   （以上拐点系本笔记据官方数字相除推导，非厂商原文给出的数字；另注意 B200 带宽早期宣称 8 TB/s、后续表述为 7.7 TB/s，引用需注明口径。）

3. **decode 的实际算术强度只有 ~1 FLOP/byte，与 H100 的 ~295 FLOP/byte 相差两个数量级。** NVIDIA 官方博客明确指出 decode 阶段"like a matrix-vector operation that underutilizes the GPU compute ability"，延迟由权重/激活从内存搬运的速度主导、"not how fast the computation actually happens"，即 memory-bound；并给出 KV cache 公式 `Total = batch × seq × 2 × num_layers × hidden_size × 2 bytes`（Llama 2 7B、seq 4096、batch=1 时约 2 GB），随 batch 与序列长度线性增长并限制吞吐。[NVIDIA blog](https://developer.nvidia.com/blog/mastering-llm-techniques-inference-optimization/)（形式化的 roofline 综述见 [arXiv:2402.16363](https://arxiv.org/abs/2402.16363)）

4. **kernel 融合 / IO-aware 优化之所以必要，正是因为激活与权重必须反复穿过 HBM。** FlashAttention 的核心论点是必须做 IO-aware 优化：用 tiling 减少 GPU HBM 与片上 SRAM 之间的读写次数，并证明其 HBM 访问次数少于标准 attention。而 decode 时 query length = 1，标准 FlashAttention 只沿 batch 与 query 维并行，若 batch 小于 SM 数（A100 为 108）则"**With a batch size of 1, FlashAttention will use less than 1% of the GPU**"；Flash-Decoding 沿 KV 序列切分并行后，把长序列解码速度最高提升 **8×**、attention kernel 本身最快 50×。[arXiv:2205.14135](https://arxiv.org/abs/2205.14135)

5. **超宽激活直接放大张量并行的同步代价。** Megatron-LM 每个 Transformer 层在 forward 路径需 2 次 all-reduce、backward 路径 2 次（每层共 4 次通信），而**通信量与 activation 张量大小 b×s×h 成正比**——h 越宽，每层需同步的字节数越大。其原始实测标尺：8.3B 模型、512 GPU、8 路模型并行下达到 15.1 PFLOP/s，相对单卡基线有 **76% 扩展效率**（即已存在约 24% 的扩展损失）。[arXiv:1909.08053](https://arxiv.org/abs/1909.08053)

6. **张量并行的跨节点"断崖"有官方公式与经验法则。** NVIDIA/Stanford 的 SC'21 论文给出每层每设备通信量 = **8·b·s·h·(t−1)/t**（h 即 hidden size），并明确：当 TP 度 t 超过单节点 GPU 数 g 时，all-reduce 必须走比 NVLink 慢得多的跨服务器链路，"**the overhead of performing tensor model parallelism across slower inter-node links can be impractical**"；经验法则是 TP 一般不超过单节点 8 卡、再往上改用 pipeline parallel。论文报告 1T 参数模型在 3072 卡上达 502 petaFLOP/s（每卡 52% of peak），并指出次优的 TP/PP 组合会造成最高 **2×** 的吞吐损失。[arXiv:2104.04473](https://arxiv.org/abs/2104.04473)

7. **NVIDIA 自己实测的同步数据量级，量化了"互联带宽决定上限"。** 单次 Llama 3.1 70B 请求（8K 输入 + 256 输出 token）需要**每张 GPU 传输多达 20 GB 的 TP 同步数据**；在仅有 128 GB/s 点对点互联的假设系统上这需要 **150 ms**，而在 NVSwitch 提供的 900 GB/s 上只需 **22 ms**（≈6.8× 差距）。官方 trillion-parameter 部署博客亦承认"scaling TP to large GPU counts without the availability of an ultra-high bandwidth GPU-to-GPU networking fabric can result in networking bottlenecks"，并在 64 卡固定预算下给出 **TP4EP4PP4 相比 TP64 吞吐高 3×** 的对比。[NVIDIA NVLink blog](https://developer.nvidia.com/blog/nvidia-nvlink-and-nvidia-nvswitch-supercharge-large-language-model-inference/) · [NVIDIA trillion-param blog](https://developer.nvidia.com/blog/demystifying-ai-inference-deployments-for-trillion-parameter-large-language-models/)

8. **"memory wall" 是可溯源的结构性问题，而非近年才有的现象。** 该术语由 Wulf & McKee 于 1995 年提出，其原始推导是："even if 80% of data is readily available in cache, and only 20% needs to be fetched from DRAM, the time to complete the operation will be completely limited by DRAM if it takes more than 5 cycles to fetch the 20% cache-miss data from it"，并总结为"Each is improving exponentially, but the exponent for microprocessors is substantially larger than that for DRAMs. The difference between diverging exponentials also grows exponentially."。《AI and Memory Wall》同时指出模型侧压力更大：LLM 参数量 **410×**/2 年、训练算力 **750×**/2 年，而单 GPU 显存仅 **2×**/2 年。[arXiv:2403.14123](https://arxiv.org/abs/2403.14123)

## 1.5 产业侧动机：为什么"token 效率"是当前核心 KPI

1. **Chinchilla 把 token 效率变成与参数量并列的核心指标。** 400+ 个模型的实验确立：compute-optimal 下参数量与训练 token 数应等比例增长（"for every doubling of model size the number of training tokens should also be doubled"），Table 3 给出 1B→20.2B、10B→205.1B、67B→1.5T、175B→3.7T、520B→11.0T、1T→21.2T，稳定在约 **20 tokens/param**。[arXiv:2203.15556](https://arxiv.org/abs/2203.15556)

2. **产业界主动偏离 Chinchilla-optimal，理由正是推理预算。** Llama 2 对 7B/13B/34B/70B **一律训练 2.0T tokens**（约 286 / 154 / 59 / 29 tokens/param，最小模型超配近 14×），论文自述理由为"a good performance-cost trade-off"。[arXiv:2307.09288](https://arxiv.org/abs/2307.09288)

3. **Llama 3 把这条逻辑写成明文策略。** 预训练语料约 **15T** tokens（Llama 2 为 1.8T），旗舰 405B 训练 **15.6T** tokens；原句："While our scaling laws suggest our flagship model is an approximately compute-optimal size for our training budget, **we also train our smaller models for much longer than is compute-optimal. The resulting models perform better than compute-optimal models at the same inference budget.**" 同文还说明用 GQA（8 个 KV 头）改善推理速度并缩小 KV cache。[arXiv:2407.21783](https://arxiv.org/abs/2407.21783)

4. **长上下文的成本被 KV cache 直接量化。** vLLM/PagedAttention 测得 13B 模型在 A100 40GB 上约 **65%** 显存给权重、接近 **30%** 给包含 KV cache 的动态状态，而"the way the KV cache is managed is critical in determining the maximum batch size"，管理低效会显著限制 batch size 与吞吐；浪费程度被实测为：**only 20.4%–38.2% of the KV cache memory is used to store the actual token states in the existing systems**（等价于 61.8%–79.6% 浪费）。单个 token 的 KV cache 需 **800 KB**，OPT-13B 单请求 2048 token 的 KV cache 可达 **1.6 GB**，即使把全部显存给 KV cache 也只能容纳几十个请求。[arXiv:2309.06180](https://arxiv.org/abs/2309.06180)

5. **long CoT 把推理成本推到新的量级。** DeepSeek-R1 以平均 **8,793 thinking tokens/题**的 test-time compute 取得 61.8% Pass@1（简单题 <7,000、最难题 >18,000 tokens，即模型自适应调节算力）；而在同一题集上 GPT-4o 0513 平均只生成 **711** output tokens——"an order of magnitude less than DeepSeek-R1"。R1-Zero 在 RL 中 response length 持续增长（"steady increase in thinking time throughout training"），训练时不得不把最大采样长度从 32,768 提高到 **65,536** tokens 作为成本控制点。[arXiv:2501.12948](https://arxiv.org/html/2501.12948v2)

6. **Kimi K2 直接把 token 效率称为"scaling 的关键系数"，并把理由归结为数据枯竭。** 1T 总参数 / 32B 激活；用 MuonClip（Muon + QK-clip，保留 Muon 的 token efficiency 并解决训练不稳定）在 **15.5T tokens** 上预训练且 **zero loss spike**。原句："Given the increasingly limited availability of high-quality human data, we posit that **token efficiency is emerging as a critical coefficient in the scaling of large language models**."[arXiv:2507.20534](https://arxiv.org/abs/2507.20534)

7. **Qwen3 用 "thinking budget" 把 token 消耗做成可调旋钮。** 系列含 6 个 dense（0.6B/1.7B/4B/8B/14B/32B）与 2 个 MoE（30B-A3B、235B-A22B），并把 thinking 与 non-thinking 模式统一到同一模型；论文明确"increasing the thinking budget for thinking tokens leads to a consistent improvement in the model's performance"，同时在极长输入上把 thinking budget 设为 **8192 tokens** 以抑制"overly verbose reasoning"——即把算力/延迟与性能的取舍显式暴露给用户。[arXiv:2505.09388](https://arxiv.org/abs/2505.09388)

8. **稀疏激活把"总容量"与"每 token 成本"解耦，这是当前 MoE 产业逻辑的核心。** DeepSeek-V3 为 **671B 总参数、每 token 仅激活 37B（≈5.5%）**，在 **14.8T** tokens 上预训练；论文对比 LLaMA-3.1 405B 时强调自身激活参数只有对方的 **1/11**。**归因提醒**：常被引用的"KV cache 减少 **93.3%**、训练成本省 **42.5%**、最大生成吞吐提升 **5.76×**"出自 **DeepSeek-V2**（与 DeepSeek 67B 对比），V3 报告本身只写 MLA"results in significantly reduced KV cache"，引用时务必归因正确。[arXiv:2412.19437](https://arxiv.org/abs/2412.19437) · [arXiv:2405.04434](https://arxiv.org/abs/2405.04434)
